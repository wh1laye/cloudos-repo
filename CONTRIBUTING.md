# как помочь

проект ведёт один человек, поэтому правки проще принять, когда они маленькие и проверены.

- уязвимости не публикуй в issue, пиши через вкладку security (см. `SECURITY.md`)
- ошибку опиши шаблоном bug: версия iso, железо, шаги, что ожидал и что получил
- перед pull request запусти то, что запускает ci: `make -C cloudpkg`, `bash tools/test-cloudpkg.sh`, `node tools/test-site.js`
- в коде без комментариев, стиль берётся из соседних файлов
- одно изменение, одна причина: не смешивай исправление и переписывание
- новые `innerHTML` на форуме проверяй на `esc()` и поднимай число в `tools/innerhtml-baseline.json` осознанно
- shell-скрипты должны проходить `shellcheck -S error`

релизы собираются в github actions, локально собранные файлы в релиз не попадают.
