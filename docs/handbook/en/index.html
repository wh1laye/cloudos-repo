              cloudos handbook

              installing cloudos live iso 2.3 on x86_64.

              1. about cloudos

              cloudos is a fast hardened x86_64 linux: openrc, vanilla kernel, limine, packages built from source with cloudpkg. it installs from the live iso with one command and boots to a plain console.

              parametervalue
              архитектураx86_64
              libcglibc
              initopenrc
              vanilla kernel from kernel.org, disk drivers built in, no initramfs needed
              загрузчикlimine
              файловые системыext4 and btrfs (zstd)
              packagesfrom source only, the cloudpkg command

              1.1 requirements

              itemguideline
              cpuany x86_64, one image for all
              ram2 gb or more
              disk10 gb or more, 20 gb if you build packages
              bootuefi or bios (up to 2 tb in bios)
              networkwired dhcp or wifi through iwctl
              mediausb stick or disc with the live iso

              1.2 what is inside

              gcc, glibc, binutils, python, openrc, udev, dhcpcd, iwd for wifi, opendoas instead of sudo, curl, git, nano, wget, rsync, openssh (disabled), nftables, gnupg, man-db, dosfstools, cloudpkg. no graphics or desktop.

              1.3 what is tuned for speed and security

              areawhat is done
              boot speedno initramfs, disks and ext4/btrfs built in, openrc starts services in parallel, zstd compressed kernel
              runtime speednoatime, btrfs with zstd compression, tcp bbr, bfq, kyber and deadline disk schedulers, schedutil, zswap and zram with zstd, thp on request only
              kernelkspp-style options: randomization, hardened usercopy, memory init, enforced module signatures, yama ptrace_scope 2, kexec, devkmem and vsyscall disabled
              networknftables with a drop policy on from the first boot, ssh off, sysctl against spoofing, redirects and source routing
              accessroot rights only through doas and the wheel group, passwords are set during install, no default passwords
              notethe image is built without -march=native, so it runs on any x86_64. an x86-64-v3 build and extra userland optimizations are planned for later.

              1.4 what is not there yet

              there is no graphics. secure boot with your own keys, a signed uki, luks2 with tpm2, apparmor and a cis check profile exist (see 5.6), selinux does not. honestly: no system is unhackable, cloudos gives a hardened baseline, not a guarantee.

              2. preparation

              2.1 writing the iso to a stick

              download the iso and checksum from the releases page and verify:

              sha256sum -c cloudos-live-amd64-2.3.iso.sha256

              write the image to the stick (careful: pick the stick, its data will be erased):

              sudo dd if=cloudos-live-amd64-2.3.iso of=/dev/sdX bs=4M status=progress conv=fsync

              2.2 logging in to the live system

              boot from the stick. login is automatic: user cloudos, password cloudos, root through doas -s. this is for the live system only, ssh is closed for these accounts and the firewall is on.

              2.3 network

              the install itself needs no network. wired comes up by itself. wifi:

              doas iwctl station wlan0 scan
doas iwctl station wlan0 get-networks
doas iwctl station wlan0 connect имя_сети
              ip addr
ping -c1 github.com

              3. one-command install

              in the live system run:

              doas cloudos-install

              the installer asks for the disk, filesystem (ext4 or btrfs), hostname, username and two passwords. then it does everything itself:

              1. partitions the disk: gpt with a 512 mb efi partition for uefi, dos with a 512 mb boot partition for bios, the rest is root
              2. formats the partitions and mounts them at /mnt/cloudos
              3. unpacks the system from the iso with unsquashfs
              4. writes fstab, installs limine and the kernel into /boot
              5. removes live leftovers, creates the user and passwords
              6. checks the result and unmounts the disk

              the installer first asks for the mode. auto wipes the whole disk you pick. manual lets you partition yourself with cfdisk, fdisk or sfdisk, then asks for the boot partition (efi system partition on uefi, vfat, 100 mb or more) and the root partition (4 gb or more). only those two partitions are touched, all other partitions and their data stay intact. an existing vfat boot partition can be kept as is, the old fallback loader is saved as BOOTX64.EFI.bak. for scripts: CLOUDOS_MODE=manual CLOUDOS_ROOT=/dev/sda3 CLOUDOS_BOOT=/dev/sda1 CLOUDOS_FORMAT_BOOT=0.

              importantin auto mode the chosen disk is erased completely, in manual mode only the root partition (and the boot partition if you format it). the installer refuses the media the iso booted from and asks you to type the disk path to confirm.

              when you see the done message run reboot and remove the stick. for scripts the installer takes variables instead of questions, see cloudos-install --help.

              4. manual install

              the same thing cloudos-install does, step by step. use it for a custom layout or to see how it works. run as root (doas -s). /dev/sda below is an example, check your disk with lsblk.

              4.1 partitioning

              sfdisk /dev/sda <<EOF
label: gpt
,512M,U
,,L
EOF
              sfdisk /dev/sda <<EOF
label: dos
,512M,c,*
,,L
EOF
              importantall data on the chosen disk is erased. on nvme the partitions are named nvme0n1p1 and nvme0n1p2.

              4.2 filesystems and mounting

              mkfs.vfat -F32 /dev/sda1
mkfs.ext4 /dev/sda2
mkdir -p /mnt/cloudos
mount -o noatime /dev/sda2 /mnt/cloudos

              btrfs with compression can replace ext4:

              mkfs.btrfs /dev/sda2
mount -o noatime,compress=zstd:1 /dev/sda2 /mnt/cloudos

              4.3 unpacking the system

              unsquashfs -f -d /mnt/cloudos /media/cdrom/cloudos/rootfs.squashfs
mkdir -p /mnt/cloudos/{proc,sys,dev,run,tmp,var/tmp,mnt,media}
chmod 1777 /mnt/cloudos/tmp /mnt/cloudos/var/tmp
mount -o umask=0077 /dev/sda1 /mnt/cloudos/boot
cp /media/cdrom/boot/vmlinuz /mnt/cloudos/boot/vmlinuz

              if the iso is not mounted at /media/cdrom, check findmnt.

              4.4 fstab

              blkid /dev/sda1 /dev/sda2

              take the UUID and PARTUUID values from the output. file /mnt/cloudos/etc/fstab:

              UUID=UUID_КОРНЯ / ext4 noatime,errors=remount-ro 0 1
UUID=UUID_BOOT /boot vfat umask=0077,noatime 0 2
tmpfs /tmp tmpfs nosuid,nodev,mode=1777 0 0

              4.5 limine bootloader

              mkdir -p /mnt/cloudos/boot/limine
nano /mnt/cloudos/boot/limine/limine.conf

              content (root partition PARTUUID from blkid, your filesystem type):

              timeout: 3

/CloudOS
    protocol: linux
    path: boot():/vmlinuz
    cmdline: root=PARTUUID=PARTUUID_КОРНЯ rootfstype=ext4 rw quiet slab_nomerge init_on_alloc=1 page_alloc.shuffle=1 randomize_kstack_offset=on vsyscall=none debugfs=off pti=on module.sig_enforce=1
              mkdir -p /mnt/cloudos/boot/EFI/BOOT
cp /usr/share/limine/BOOTX64.EFI /usr/share/limine/BOOTIA32.EFI /mnt/cloudos/boot/EFI/BOOT/
              cp /usr/share/limine/limine-bios.sys /mnt/cloudos/boot/limine/
limine bios-install /dev/sda

              4.6 configuration inside

              mount --rbind /dev /mnt/cloudos/dev
mount -t proc proc /mnt/cloudos/proc
mount --rbind /sys /mnt/cloudos/sys
mount -t tmpfs tmpfs /mnt/cloudos/run
chroot /mnt/cloudos /bin/bash

              inside the chroot remove live leftovers, create the user and passwords:

              rm -f /etc/init.d/cloudos-smoke /etc/runlevels/default/cloudos-smoke /etc/conf.d/agetty.tty1 /etc/ssh/sshd_config.d/05-cloudos-live.conf
userdel -r cloudos
useradd -m -G wheel,users,video,audio,netdev -s /bin/bash имя
passwd имя
passwd
echo "permit persist :wheel" > /etc/doas.conf
chmod 600 /etc/doas.conf
echo 'hostname="cloudos"' > /etc/conf.d/hostname

              4.7 finishing

              exit
umount -R /mnt/cloudos
reboot

              5. after the install

              5.1 login and rights

              log in as the user you created. root commands go through doas:

              doas cloudpkg install nano

              5.2 timezone and hostname

              ls /usr/share/zoneinfo
doas ln -sfv /usr/share/zoneinfo/Europe/Moscow /etc/localtime
date

              5.3 network

              dhcpcd gets an address by itself. for wifi:

              doas iwctl station wlan0 connect имя_сети
ip addr

              a static address goes into /etc/dhcpcd.conf.

              5.4 services and firewall

              rc-update show
doas rc-service sshd start
doas rc-update add sshd default
doas cloudos-firewall status
doas cloudos-audit

              ssh is off by default and the nftables firewall runs with a drop policy. open the port with cloudos-firewall before enabling sshd (run cloudos-firewall with no arguments for help).

              5.5 swap and zram

              swap is optional. as a file:

              doas dd if=/dev/zero of=/swapfile bs=1M count=4096 status=progress
doas chmod 600 /swapfile
doas mkswap /swapfile
doas swapon /swapfile

              plus a line in /etc/fstab: /swapfile none swap defaults 0 0. the kernel supports zswap and zram with zstd.

              5.6 hardening: apparmor, uki, tpm2, cis

              apparmor is built into the kernel and starts in boot. profiles from apparmor-profiles ship in complain mode (log only). switch one to enforce: doas aa-enforce /etc/apparmor.d/name. state: doas aa-status.

              signed uki: kernel, initramfs and kernel command line in one file signed with your db key. enable it at install time (CLOUDOS_SECUREBOOT=1 CLOUDOS_UKI=1) or later: doas cloudos-uki build && doas cloudos-secureboot sign. the command line is baked in and cannot be changed at boot. repeat after every kernel update.

              tpm2 for luks: doas cloudos-tpm2 enroll seals the disk key in the tpm2 against pcr 7 (secure boot state) and adds luks slot 7. run it when secure boot is already on and you booted with it. if keys change, secure boot is turned off or the disk moves, the tpm will not release the key and the system asks for the luks passphrase. the passphrase always keeps working, store it. remove: doas cloudos-tpm2 remove.

              cis profile: doas cloudos-audit --cis adds checks for file permissions, passwords, disabled rare filesystems, network settings and ssh. these are checks inspired by the cis benchmark, not a certification.

              6. packages and cloudpkg

              cloudpkg builds packages from source using gentoo based recipes.

              doas cloudpkg sync
cloudpkg search имя
cloudpkg info имя
doas cloudpkg install имя
doas cloudpkg remove имя
doas cloudpkg upgrade
doas cloudpkg clean

              if a package fails, read the last log lines and look in errors and fixes. builds need free space in /var/tmp and enough ram.

              7. your own kernel (optional)

              the kernel from the iso fits most machines and needs no tuning. build your own only if you need a driver the image lacks. gcc, make and the rest are already installed.

              cd /usr/src
curl -LO https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.18.10.tar.xz
tar xf linux-6.18.10.tar.xz
cd linux-6.18.10
zcat /proc/config.gz > .config 2>/dev/null || make defconfig
make menuconfig
make -j$(nproc)
doas make modules_install
doas cp arch/x86/boot/bzImage /boot/vmlinuz-6.18.10

              add a second entry to /boot/limine/limine.conf with path: boot():/vmlinuz-6.18.10 and reboot. the disk driver and root filesystem must be built in (=y) since there is no initramfs. the cmdline has module.sig_enforce=1: modules of your own kernel must be signed or the parameter removed.

              8. maintenance

              doas cloudpkg sync
doas cloudpkg upgrade
doas cloudpkg clean
df -h

              system updates ship as new live iso versions: reinstall or update packages with cloudpkg. backup:

              doas tar cpf /mnt/usb/cloudos-backup.tar.xz --xattrs-include='*.*' --numeric-owner --one-file-system -I xz /

              9. errors and fixes

              problemwhat to do
              installer says mkfs.btrfs is missingthis iso has no btrfs-progs, choose ext4
              installer sees no diskcheck lsblk. the iso media is excluded on purpose
              uefi does not boot after installpick the disk in the firmware boot menu. the file must be at /boot/EFI/BOOT/BOOTX64.EFI
              kernel panic: unable to mount rootcompare root=PARTUUID= in limine.conf with blkid. controllers other than sata, nvme, virtio and usb storage may need your own kernel, see 7
              no wifidoas iwctl station wlan0 scan, then connect. firmware is already in the system
              forgot the passwordboot the live iso, mount root at /mnt/cloudos, chroot, passwd
              a package failed to builddoas cloudpkg sync and retry. if it fails, post the last log lines on the forum

              11. questions

              can it run on a server

              yes, with honest limits in mind: updates are manual. cloudpkg update verifies signatures, but apparmor profiles ship in complain mode and you must enforce them yourself. for critical systems judge the risks yourself.

              what happened to stage 3

              a separate stage 3 is no longer published. the system installs straight from the live iso and the handbook covers only that way.

              why no secure boot

              it already exists: CLOUDOS_SECUREBOOT=1 in the installer and the cloudos-secureboot command (own keys, signed limine, kernel hashes). a signed unified kernel image is added with CLOUDOS_UKI=1.
