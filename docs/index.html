cloudos handbook

установка cloudos 1.0 на x86_64.

1. о cloudos

cloudos это минимальный linux, который ты собираешь сам. после установки в системе только консоль.

параметрзначение
архитектураx86_64
libcglibc
initopenrc
ядрованильное с kernel.org
загрузчикlimine
файловые системыext4 и btrfs
пакетытолько из исходников, команда cloudpkg
заметкаhandbook рассчитан на тех, кто готов разбираться. скриптов и автоустановки нет.

2. подготовка

загрузись с live iso cloudos и проверь сеть.

dhcpcd
ping -c1 github.com

определи режим загрузки. 

[ -d /sys/firmware/efi ] && echo uefi || echo bios

3. диск и файловые системы

3.1 разметка

cfdisk /dev/sda
режимтаблицаразделы
uefigptsda1 512 мб, тип efi system. sda2 остальное
biosdossda1 512 мб, флаг bootable, это /boot. sda2 остальное
важновсе данные на диске(только на том, который ты выбрал)

3.2 файловые системы

для uefi раздел /boot форматируется в fat32:

mkfs.fat -F32 /dev/sda1

для bios раздел /boot всегда f32, потому что limine не читает btrfs:

mkfs.fat -F32 /dev/sda1

корневой раздел форматируй в ext4:

mkfs.ext4 /dev/sda2

или в btrfs:

mkfs.btrfs /dev/sda2

3.3 монтирование

mkdir -p /mnt/cloudos
mount /dev/sda2 /mnt/cloudos
mkdir -p /mnt/cloudos/boot
mount /dev/sda1 /mnt/cloudos/boot

4. stage 3

stage 3 это готовая базовая система cloudos без ядра и загрузчика. файлы лежат в разделе releases репозитория.

github.com/wh1laye/cloudos-repo/releases

cloudos-stage3-1.0-x86_64.tar.xz
cloudos-stage3-1.0-x86_64.tar.xz.sha256

4.1 проверка(можно пропустить)

sha256sum -c cloudos-stage3-1.0-x86_64.tar.xz.sha256

4.2 распаковка

tar xpvf cloudos-stage3-1.0-x86_64.tar.xz --xattrs-include='*.*' --numeric-owner -C /mnt/cloudos

5. вход в chroot

mount --types proc /proc /mnt/cloudos/proc
mount --rbind /sys /mnt/cloudos/sys
mount --make-rslave /mnt/cloudos/sys
mount --rbind /dev /mnt/cloudos/dev
mount --make-rslave /mnt/cloudos/dev
cp --dereference /etc/resolv.conf /mnt/cloudos/etc/
chroot /mnt/cloudos /bin/bash
source /etc/profile

6. настройка сборки

флаги сборки задаются в одном файле, /etc/cloudpkg/make.conf:

CC="gcc"
CFLAGS="-O2 -march=native"
MAKEOPTS="-j12"
USE=""

для clang поставь CC="clang". потом обнови список рецептов:

cloudpkg sync

6.1 локали

echo "en_US.UTF-8 UTF-8" > /etc/locale.gen
localedef -i en_US -f UTF-8 en_US.UTF-8
echo "LANG=en_US.UTF-8" > /etc/locale.conf

7. ядро

ядро берётся с kernel.org и настраивается вручную 

cd /usr/src
curl -LO https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.18.10.tar.xz
tar xf linux-6.18.10.tar.xz
cd linux-6.18.10
make menuconfig
make -j$(nproc)
make modules_install
cp arch/x86/boot/bzImage /boot/vmlinuz-6.18.10
важно вам нужно использовать везде имя диска на который вы хотите ставить, узнать можно с помощью команды lsblk(опять же, диск может называться /dev/nvme0n1 /dev/sda /dev/sdb

8. загрузчик

8.1 initramfs

cloudpkg install dracut
dracut --kver 6.18.10 /boot/initramfs-6.18.10.img

8.2 fstab

uuid разделов покажет blkid. файл /etc/fstab для uefi:

UUID=ROOT_UUID  /      ext4  defaults  0 1
UUID=ESP_UUID   /boot  vfat  defaults  0 2

для bios:

UUID=ROOT_UUID  /      ext4  defaults  0 1
UUID=BOOT_UUID  /boot  vfat  defaults  0 2

если корень на btrfs, замени ext4 в первой строке на btrfs.

8.3 limine

cloudpkg install limine

файл /boot/limine.conf одинаковый для uefi и bios:

timeout: 5

/CloudOS
    protocol: linux
    path: boot():/vmlinuz-6.18.10
    cmdline: root=UUID=ROOT_UUID rw
    module_path: boot():/initramfs-6.18.10.img

установка для uefi:

mkdir -p /boot/EFI/BOOT
cp /usr/share/limine/BOOTX64.EFI /boot/EFI/BOOT/BOOTX64.EFI

установка для bios, ставь на весь диск, а не на раздел:

cp /usr/share/limine/limine-bios.sys /boot/
limine bios-install /dev/(твое имя диска /dev/sda1 /dev/sdb1 /dev/nvme0n1)

9. завершение

включи сеть и журнал, задай пароль root:

cloudpkg install dhcpcd
cloudpkg install syslog-ng
rc-update add dhcpcd default
rc-update add syslog-ng default
passwd

выйди из chroot, размонтируй и перезагрузись:

exit
umount -R /mnt/cloudos
reboot
заметкадругих пользователей cloudos не создаёт!), пользователя и doas добавишь сам.
важнодиск на который вы ставите может быть как NVME так и sda sdb, тестил на 7 5700X(AMD) RX9060XT(AMD) и на sda(не nvme limine выбрал изза скорости и удобства, поддержка grub ВОЗМОЖНО будет.
