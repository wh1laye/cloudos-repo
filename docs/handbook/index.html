              cloudos справочник

              установка cloudos live iso 2.3 на x86_64.

              1. о cloudos

              cloudos это быстрый и усиленный linux для x86_64: openrc, ванильное ядро, limine, пакеты из исходников через cloudpkg. ставится с live iso одной командой, после установки в системе только консоль.

              параметрзначение
              архитектураx86_64
              libcglibc
              initopenrc
              ядро с kernel.org, драйверы дисков встроены, initramfs не нужен
              загрузчикlimine
              файловые системыext4 и btrfs (zstd)
              пакетытолько из исходников, команда cloudpkg

              1.1 что нужно

              чтоориентир
              процессорлюбой x86_64, один образ для всех
              озуот 2 гб
              дискот 10 гб, под сборку пакетов лучше 20 гб
              загрузкаuefi или bios (в bios диск до 2 тб)
              сетьпроводная по dhcp или wifi через iwctl
              носительфлешка или диск с live iso

              1.2 что внутри

              gcc, glibc, binutils, python, openrc, udev, dhcpcd, iwd для wifi, opendoas вместо sudo, curl, git, nano, wget, rsync, openssh (выключен), nftables, gnupg, man-db, dosfstools, cloudpkg. графики и окружений нет.

              1.3 что настроено на скорость и защиту

              областьчто сделано
              скорость загрузкиядро без initramfs, диски и ext4/btrfs встроены, openrc запускает службы параллельно, ядро сжато zstd
              скорость работыnoatime, btrfs со сжатием zstd, tcp bbr, планировщики дисков bfq, kyber и deadline, schedutil, zswap и zram с zstd, thp только по запросу
              ядроkspp-набор опций: рандомизация, hardened usercopy, инициализация памяти, обязательная подпись модулей, yama ptrace_scope 2, lockdown-подобные ограничения, отключены kexec, devkmem, vsyscall
              сетьnftables с политикой drop включён сразу, ssh выключен, sysctl с защитой от spoofing, redirect и source routing
              доступroot-права только через doas и группу wheel, пароли задаются при установке, паролей по умолчанию нет
              заметкаобраз собран без -march=native, поэтому работает на любом x86_64. сборка под x86-64-v3 и дополнительные оптимизации userland запланированы позже.

              1.4 чего пока нет

              графики нет. secure boot на своих ключах, подписанный uki, luks2 с tpm2, apparmor и профиль проверки cis есть (см. 5.6), selinux нет. честно: полностью неуязвимых систем не бывает, cloudos даёт усиленную базовую конфигурацию, а не гарантию.

              2. подготовка

              2.1 запись iso на флешку

              скачай iso и контрольную сумму со страницы релизов и проверь:

              sha256sum -c cloudos-live-amd64-2.3.iso.sha256

              запиши образ на флешку (внимание: выбери именно флешку, её данные сотрутся):

              sudo dd if=cloudos-live-amd64-2.3.iso of=/dev/sdX bs=4M status=progress conv=fsync

              2.2 вход в live

              загрузись с флешки. вход автоматический: пользователь cloudos, пароль cloudos, root-права через doas -s. это только для live, ssh для этих учётных записей закрыт, фаервол включён.

              2.3 сеть

              для установки сеть не нужна. проводная сеть поднимается сама. wifi:

              doas iwctl station wlan0 scan
doas iwctl station wlan0 get-networks
doas iwctl station wlan0 connect имя_сети
              ip addr
ping -c1 github.com

              3. установка одной командой

              в live выполни:

              doas cloudos-install

              установщик спросит диск, файловую систему (ext4 или btrfs), имя компьютера, имя пользователя и два пароля. дальше он сам делает всё:

              1. размечает диск: gpt и efi раздел 512 мб для uefi, dos и загрузочный раздел 512 мб для bios, остальное под корень
              2. форматирует разделы и монтирует их в /mnt/cloudos
              3. распаковывает систему из iso через unsquashfs
              4. пишет fstab, ставит limine и ядро в /boot
              5. убирает следы live, создаёт пользователя и пароли
              6. проверяет результат и размонтирует диск

              сначала установщик спрашивает режим. auto стирает весь выбранный диск. manual даёт разметить диск самому через cfdisk, fdisk или sfdisk, потом спрашивает раздел для boot (efi раздел при uefi, vfat, от 100 мб) и раздел для root (от 4 гб). трогаются только эти два раздела, остальные разделы и данные остаются. существующий vfat раздел boot можно оставить как есть, старый загрузчик сохраняется как BOOTX64.EFI.bak. для скриптов: CLOUDOS_MODE=manual CLOUDOS_ROOT=/dev/sda3 CLOUDOS_BOOT=/dev/sda1 CLOUDOS_FORMAT_BOOT=0.

              важнов режиме auto выбранный диск стирается целиком, в manual только раздел root (и boot, если форматируешь его). установщик не даёт выбрать носитель, с которого загружен iso, и просит ввести путь диска для подтверждения.

              когда увидишь «готово», выполни reboot и вытащи флешку. без вопросов (для скриптов) установщик запускается переменными, список по cloudos-install --help.

              4. установка вручную

              то же самое, что делает cloudos-install, по шагам. нужно, если хочешь свою разметку, другую точку монтирования или просто понять, как это устроено. команды выполняй от root (doas -s). ниже /dev/sda это пример, смотри свой диск в lsblk.

              4.1 разметка

              sfdisk /dev/sda <<EOF
label: gpt
,512M,U
,,L
EOF
              sfdisk /dev/sda <<EOF
label: dos
,512M,c,*
,,L
EOF
              важновсе данные на выбранном диске сотрутся. для nvme разделы называются nvme0n1p1 и nvme0n1p2.

              4.2 файловые системы и монтирование

              mkfs.vfat -F32 /dev/sda1
mkfs.ext4 /dev/sda2
mkdir -p /mnt/cloudos
mount -o noatime /dev/sda2 /mnt/cloudos

              вместо ext4 можно btrfs со сжатием:

              mkfs.btrfs /dev/sda2
mount -o noatime,compress=zstd:1 /dev/sda2 /mnt/cloudos

              4.3 распаковка системы

              unsquashfs -f -d /mnt/cloudos /media/cdrom/cloudos/rootfs.squashfs
mkdir -p /mnt/cloudos/{proc,sys,dev,run,tmp,var/tmp,mnt,media}
chmod 1777 /mnt/cloudos/tmp /mnt/cloudos/var/tmp
mount -o umask=0077 /dev/sda1 /mnt/cloudos/boot
cp /media/cdrom/boot/vmlinuz /mnt/cloudos/boot/vmlinuz

              если iso записан на флешку и смонтирован не в /media/cdrom, смотри findmnt.

              4.4 fstab

              blkid /dev/sda1 /dev/sda2

              возьми значения UUID и PARTUUID из вывода. файл /mnt/cloudos/etc/fstab:

              UUID=UUID_КОРНЯ / ext4 noatime,errors=remount-ro 0 1
UUID=UUID_BOOT /boot vfat umask=0077,noatime 0 2
tmpfs /tmp tmpfs nosuid,nodev,mode=1777 0 0

              4.5 загрузчик limine

              mkdir -p /mnt/cloudos/boot/limine
nano /mnt/cloudos/boot/limine/limine.conf

              содержимое (PARTUUID корневого раздела из blkid, тип файловой системы свой):

              timeout: 3

/CloudOS
    protocol: linux
    path: boot():/vmlinuz
    cmdline: root=PARTUUID=PARTUUID_КОРНЯ rootfstype=ext4 rw quiet slab_nomerge init_on_alloc=1 page_alloc.shuffle=1 randomize_kstack_offset=on vsyscall=none debugfs=off pti=on module.sig_enforce=1
              mkdir -p /mnt/cloudos/boot/EFI/BOOT
cp /usr/share/limine/BOOTX64.EFI /usr/share/limine/BOOTIA32.EFI /mnt/cloudos/boot/EFI/BOOT/
              cp /usr/share/limine/limine-bios.sys /mnt/cloudos/boot/limine/
limine bios-install /dev/sda

              4.6 настройка внутри

              mount --rbind /dev /mnt/cloudos/dev
mount -t proc proc /mnt/cloudos/proc
mount --rbind /sys /mnt/cloudos/sys
mount -t tmpfs tmpfs /mnt/cloudos/run
chroot /mnt/cloudos /bin/bash

              внутри chroot убери следы live, создай пользователя и пароли:

              rm -f /etc/init.d/cloudos-smoke /etc/runlevels/default/cloudos-smoke /etc/conf.d/agetty.tty1 /etc/ssh/sshd_config.d/05-cloudos-live.conf
userdel -r cloudos
useradd -m -G wheel,users,video,audio,netdev -s /bin/bash имя
passwd имя
passwd
echo "permit persist :wheel" > /etc/doas.conf
chmod 600 /etc/doas.conf
echo 'hostname="cloudos"' > /etc/conf.d/hostname

              4.7 завершение

              exit
umount -R /mnt/cloudos
reboot

              5. после установки

              5.1 вход и права

              входи под созданным пользователем. команды от root выполняются через doas:

              doas cloudpkg install nano

              5.2 часовой пояс и имя

              ls /usr/share/zoneinfo
doas ln -sfv /usr/share/zoneinfo/Europe/Moscow /etc/localtime
date

              5.3 сеть

              dhcpcd получает адрес сам. для wifi:

              doas iwctl station wlan0 connect имя_сети
ip addr

              постоянный адрес задаётся в /etc/dhcpcd.conf.

              5.4 службы и фаервол

              rc-update show
doas rc-service sshd start
doas rc-update add sshd default
doas cloudos-firewall status
doas cloudos-audit

              ssh по умолчанию выключен, фаервол nftables включён с политикой drop. перед включением sshd открой порт командами cloudos-firewall (см. cloudos-firewall без аргументов).

              5.5 swap и zram

              swap не обязателен. файлом:

              doas dd if=/dev/zero of=/swapfile bs=1M count=4096 status=progress
doas chmod 600 /swapfile
doas mkswap /swapfile
doas swapon /swapfile

              и строка в /etc/fstab: /swapfile none swap defaults 0 0. ядро поддерживает zswap и zram со сжатием zstd.

              5.6 защита: apparmor, uki, tpm2, cis

              apparmor включён в ядре и стартует в boot. профили из apparmor-profiles идут в режиме complain (только пишут в лог). переведи нужный в enforce: doas aa-enforce /etc/apparmor.d/имя. состояние: doas aa-status.

              подписанный uki: ядро, initramfs и параметры ядра в одном файле, подписанном твоим ключом db. включается при установке (CLOUDOS_SECUREBOOT=1 CLOUDOS_UKI=1) или потом: doas cloudos-uki build && doas cloudos-secureboot sign. параметры зашиты в образ и при загрузке не меняются. после каждого обновления ядра команды нужно повторить.

              tpm2 для luks: doas cloudos-tpm2 enroll запечатывает ключ диска в tpm2 по pcr 7 (состояние secure boot) и добавляет слот 7. запускай, когда secure boot уже включён и система с ним загружена. при смене ключей, выключении secure boot или переносе диска tpm ключ не отдаст, и система спросит пароль luks. пароль остаётся рабочим всегда, сохрани его. убрать: doas cloudos-tpm2 remove.

              профиль cis: doas cloudos-audit --cis добавляет к проверке права на файлы, пароли, отключённые лишние файловые системы, сетевые параметры и ssh. это проверки по мотивам cis benchmark, а не сертификация.

              6. пакеты и cloudpkg

              cloudpkg ставит пакеты из исходников по рецептам, основанным на gentoo.

              doas cloudpkg sync
cloudpkg search имя
cloudpkg info имя
doas cloudpkg install имя
doas cloudpkg remove имя
doas cloudpkg upgrade
doas cloudpkg clean

              если пакет не собрался, смотри последние строки лога и поищи ошибку в разделе ошибки и решения. для сборки нужно место в /var/tmp и достаточно озу.

              7. своё ядро (по желанию)

              ядро из iso подходит для большинства машин, его настраивать не нужно. свою сборку делают, если нужен драйвер, которого нет в образе. в системе уже есть gcc, make и всё нужное.

              cd /usr/src
curl -LO https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.18.10.tar.xz
tar xf linux-6.18.10.tar.xz
cd linux-6.18.10
zcat /proc/config.gz > .config 2>/dev/null || make defconfig
make menuconfig
make -j$(nproc)
doas make modules_install
doas cp arch/x86/boot/bzImage /boot/vmlinuz-6.18.10

              добавь второй пункт в /boot/limine/limine.conf с path: boot():/vmlinuz-6.18.10 и перезагрузись. диск и корневая файловая система должны быть встроены в ядро (=y), так как initramfs нет. в cmdline стоит module.sig_enforce=1: модули своего ядра нужно подписывать или убрать этот параметр.

              8. обслуживание

              doas cloudpkg sync
doas cloudpkg upgrade
doas cloudpkg clean
df -h

              обновления самой системы выходят новыми версиями live iso: ставь заново или обновляй пакеты через cloudpkg. резервная копия:

              doas tar cpf /mnt/usb/cloudos-backup.tar.xz --xattrs-include='*.*' --numeric-owner --one-file-system -I xz /

              9. ошибки и решения

              проблемачто делать
              установщик пишет «нет mkfs.btrfs»в этом iso нет btrfs-progs, выбери ext4
              установщик не видит дискпроверь lsblk. диск с iso исключён намеренно

              нет сети по wifidoas iwctl station wlan0 scan, затем connect. прошивки уже в системе
              забыл парользагрузись с live iso, смонтируй корень в /mnt/cloudos, chroot, passwd
              пакет не собралсяdoas cloudpkg sync и повтор. при ошибке сообщи на форуме с последними строками лога

              11. вопросы и ответы

              можно ли ставить на сервер

              можно, но помни про честные пределы: обновления выходят вручную. cloudpkg update проверяет подпись, но профили apparmor по умолчанию в режиме complain и их нужно включать самому. для критичных систем сам оцени риски.

              куда делся stage 3

              отдельный stage 3 больше не выпускается. система ставится прямо из live iso, а справочник описывает только этот способ.

              почему нет secure boot

              это уже есть: CLOUDOS_SECUREBOOT=1 в установщике и команда cloudos-secureboot (свои ключи, подпись limine, хеши ядра). подписанный unified kernel image добавляется через CLOUDOS_UKI=1.
