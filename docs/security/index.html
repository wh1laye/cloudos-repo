безопасность

что cloudos защищает, что для этого включено, чего пока нет и как сообщить об уязвимости. всё ниже взято из файлов репозитория, в таблице указано, из каких.

модель угроз

угрозачто делает система
атака по сетифаервол с политикой drop на входе, ssh только по ключам, лишние сетевые протоколы отключены
повышение прав локальным пользователемядро с kspp-опциями, ограничения ptrace, bpf, kexec, dmesg, root только через doas
подмена iso или исходниковsha256 исходников, stage 3 и iso, подпись minisign, attestation происхождения в github actions
кража дискаluks2 по желанию, опционально tpm2 (pcr 7)
подмена загрузчика и ядраsecure boot со своими ключами, подпись limine, хеши ядра, uki (только uefi)

чего пока нет

  • профили apparmor из apparmor-profiles идут в режиме complain, в enforce их переводит владелец системы
  • uki, tpm2 и модуль dracut не проверены на железе
  • tpm2 привязан к pcr 7 (состояние secure boot), а не к хешу ядра
  • ключ подписи minisign хранится в секретах github actions: подпись доказывает, что файл собран workflow проекта, а не что ключ лежит офлайн
  • независимого аудита кода и сборки нет
  • live iso содержит известный пароль (пользователь cloudos, пароль cloudos), ssh для него закрыт; в stage 3 и установленной системе его нет

как проверить скачанное

страница проверки сверяет sha256 и подпись файла из релиза прямо в браузере.

как сообщить об уязвимости

не пиши об уязвимости в публичный issue. открой приватное сообщение на github (вкладка security, report a vulnerability). укажи версию, шаги воспроизведения и что можно сделать с уязвимостью.
